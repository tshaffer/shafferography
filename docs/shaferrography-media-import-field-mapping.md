## Findings

A) What is uniqueId? Where computed?
- uniqueId is a UUID v4 generated during local import. It is not a hash and not derived from Google IDs. Computed in `buildMediaItemFromLocal` via `uuidv4()`.

B) Is creationTime always copied from exif.takenAt? If not, why?
- No. creationTime prefers `DateTimeOriginal`, then `CreateDate`. exif.takenAt only uses `DateTimeOriginal`. If `DateTimeOriginal` is missing but `CreateDate` exists, creationTime is set while exif.takenAt is null. Reimport follows the same precedence.

C) What exactly is lastModified? (canonical file mtime? source file mtime?)
- It is the file mtime in UTC ISO. During directory imports, if a `FileToImport.lastModified` epoch value is provided, that is used (converted to UTC ISO). Otherwise it falls back to `fs.statSync(...).mtime` via `getLastModifiedUTCISO`. Reimport always uses `getLastModifiedUTCISO`.

D) Where do googleMediaItemId / googleAlbumId / googleAlbumName come from, if at all?
- On local import they are set from parameters (albumId/albumName) with defaults of empty string and googleMediaItemId is set to empty string. After upload-to-Google, `googleMediaItemId`, `googleAlbumId`, and `googleAlbumName` are updated with values returned by the Google Photos API in `uploadToGoogleEndpoint`.

E) Do we populate peopleRetrievedFromGoogle / people? If yes, from where?
- Initially, import sets `peopleRetrievedFromGoogle=false` and `people=[]`. The `mergePeople` flow reads Google Takeout supplemental metadata JSON (per-file `*.supplemental-metadata.json`) and sets `people` plus `peopleRetrievedFromGoogle=true` (and also updates `keywordNodeIds`). This runs via `mergePeopleTakeoutEndpoint`; the automatic call from import is currently commented out.

F) Do we populate ExifMeta.sourcePathHash? If yes, what hash and of what?
- Not currently. The schema includes `sourcePathHash`, but there is no code that sets it.

G) Time normalization: are takenAt/exif times stored in UTC ISO? Are offsets stored? How used?
- EXIF timestamps are normalized via `toIsoString` which uses `ExifDateTime.toISOString()` or `new Date(string).toISOString()`, yielding UTC ISO strings. Filesystem mtime uses Luxon `toUTC().toISO()`. Offset fields (`offsetTime`, `offsetTimeOriginal`, `offsetTimeDigitized`) are stored as raw strings from EXIF tags but are not used elsewhere in the import path.
